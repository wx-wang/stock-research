# 行业方法沉淀

## 三层资料各司其职

- 通用行业 skill：保留供需、竞争、利润池、状态变化与终局推演的方法。
- 行业专门方法：保存行业边界、关键单位、数据入口、领先指标、传导时滞、计算口径、常见误判和证伪方法。
- 动态研究档案：保存有截止日的价格、库存、产能、公司地位、预测与结论，按日期更新，不能当成永久方法。

行业研究开始时先查本目录的 `行业方法索引.md`，读取匹配的专门方法；没有则用通用行业 skill。专门方法可以补充适用的研究顺序和指标，不削弱证据、现金流及独立估值纪律。

## 日常沉淀

券商研报也是方法学习的来源。阅读时按[券商研报阅读规则](券商研报阅读与方法提炼.md)拆解作者的研究切入点、行业划分、指标、数据方法、因果逻辑和投资叙事；先还原作者思路，再独立评价，不只摘录结论。方法笔记保留作者、报告日期和关键页码，按适用条件与验证状态决定是否复用。

一次研究完成后，如果出现可复用发现，更新 `研究输出/行业方法/<行业名>/方法笔记.md`。记录：

| 字段 | 内容 |
|---|---|
| 方法主张 | 应该如何研究或核验，而非当前应看多/看空 |
| 适用边界 | 子行业、地区、技术路线、周期状态 |
| 机制与使用方式 | 指标定义、单位、公式、数据入口及传导链 |
| 支持实例 | 带日期研究报告与原始证据链接 |
| 反例与失效条件 | 哪些情境会误导、怎样辨别假信号 |
| 验证状态 | 待验证方法假设、已复用、需修订；附理由 |
| 修订记录 | 日期、旧判断、新判断及修改原因 |

例如“检验公告产能、认证产能与合格交付能力的差别”可成为方法；“今年产能紧张”应保留在动态报告中。单次相关性不能固化成领先关系；必须说明机制、样本限制及反例。

## 何时形成专门 skill

无需凑够固定研究次数。满足以下条件时，可以在本项目内创建或更新专门 skill，并在交付中说明：

- 存在跨公司或跨报告期可复用的行业差异，通用 skill 无法充分表达；
- 有明确机制、可核验的应用实例与边界，关键规则不只依靠一次行情；
- 反例与常见误判已整理，暂未验证内容与可执行方法分开；
- 用户再次提出该行业问题时，能具体改善数据获取、口径或推理。

创建/更新时使用 skill-creator 技能。放在 `Skills/industries/<industry-name>/`，必要内容为 `SKILL.md`，较长的行业细则按需放 references。不要复制通用行业 skill 全文，也不把过期事实、密钥或旧股票推荐写进 skill。

入口说明适用范围、何时读取哪些资料，以及如何向通用行业终局底稿提供行业特有输入。引用动态档案时核对日期和适用性，不沿用旧事实。已有技能更新保存关键规则的修订依据，不让历史结论悄悄改变。

## 校验与发现

创建后检查命名、前置信息、引用链接和未完成占位；用一个真实已归档问题检查是否能找到数据、区分假信号并形成可证伪结论。无需为测试另行抓取昂贵数据或制造完整虚构研报。

在 `研究规则/行业方法索引.md` 登记行业边界、相对 skill 路径、版本日期、依据和限制。AGENTS.md 通过此索引显式读取项目内技能，因此不依赖全局技能列表自动发现。全局安装或同步仅在另行请求时执行。

缺乏成熟证据时继续留在方法笔记，不为数量创建空 skill。方法过时或发现反例时修订或停用，并保留历史原因。
