# 财务计算脚本与 Skill 接入方案

状态：原设计方案存档；用户随后已授权实施，正在开发与验收。以下保留最初设计及估计，不将其作为已完成清单。最新分工按用户修订为：主任务设计整体架构，Sol High 细化接口、独立测试和复核，Luna Max 主要开发，主任务最终复核及两个 Skill / AGENTS 接入。实施口径见[本轮实现总设计](../../research_data/财务计算开发/20260923/architecture.md)。

## 目标与范围

把可重复的数字工作交给经过独立验证的程序，让研究者负责输入依据、会计调整与经营假设。目标是相同数据快照、计算规则版本、参数和数值精度产生相同财务结果；更新后能解释差异来自数据修正、公式变化还是假设变化。可复现不等于输入事实已核实，也不等于估值可靠。

首期覆盖沪深 A 股的历史财务计算及通用估值计算基础。银行、保险、券商必须识别并限制通用工业指标和估值模型；专属指标与模型分批支持，不为覆盖率强行套用。港股暂不承诺完整支持，后续单独验证接口、币种、报表期间及股份类别。

复用本次50家公司保存的原始数据开展离线回放，不重新启动50家公司完整研究。新增取数仍优先由已安装的 Tushare MCP 执行，脚本负责接收原始返回、核对、计算与归档，不另建一套私自保管凭证的取数系统。

## 数据与计算如何稳定

每次任务保存原始返回、接口参数、检索时间、研究截止日、原始文件摘要以及数据和规则版本。原始记录不覆盖；重算结果另存版本。每个结果能追到输入字段、原始记录、公式、调整项和舍入方法。

明确定义数据状态：有效、缺失、存在冲突、不可比、不适用。计算阶段另区分成功、缺输入、模型不适用、求解失败；研究阶段是否证据充分独立记录。程序退出成功不能把“研究受限”变成“完整通过”。

采用固定字段字典和公式注册表，不让每家公司单独生成一份计算程序。财务金额按明确精度计算，展示时才舍入；幂运算和求根指定误差与容差。时间采用显式估值日、现金流日与统一年数约定，不把历史年报日自动当估值起点。

更新时区分：公司新披露/重述、数据供应商修订、口径策略变化、计算代码变化、研究假设变化。基于原报确认的修正写入有来源的调整层，不悄悄改原始数据。

## 现有程序如何处理

已查看 `Skills/narrative-valuation/scripts/narrative_dcf.py` 及其测试。它已有几何增长路径、现金/利润基础、四类终值、反推终局倍数和敏感性计算，适合作为复用基础。

当前接口主要采用整年时点与正初始基准，没有显式估值日、逐笔现金支付日及独立分红/股份变动时间表。现有测试主要覆盖部分往返一致性与参数校验；本次只阅读，未运行测试，不能声称已全面验收。

实施时先由独立审查者检查公式、量纲、适用边界和测试，再决定保留解析接口或新增明确日期的计算接口。保留现有调用兼容性或提供可验证迁移方式，不另写一套同名但口径不同的DCF。对方法文档中的简化关系也先确认量纲、利润归属和资本投入定义，不能把含糊描述直接固化为代码。

## 子 Agent 分工

分工依据本次试跑暴露的问题和任务风险，不是对模型能力的严格排名。拟采用主任务统筹、最多三个子 Agent 同时工作的方式；下列角色按阶段复用，不同时启动六个长期任务。主任务实际模型继续如实记录。

| 角色 | 拟用模型 | 任务及交付物 | 独立复核 |
|---|---|---|---|
| 数据和口径开发 | Sol | 原始数据适配、版本选择、可比性、缺失/冲突处理；交付模块、样例与边界说明 | 独立Sol按原报及预先准备样例复核 |
| 财务计算开发 | Sol | 历史期间、财务比率、调整表、适用性规则；第二阶段完善现金、股份与DCF | 主任务检查高风险口径，独立Sol检查结果和代码 |
| 通用输出辅助 | Luna | 在已冻结格式上做结果导出、报告字段引用、文件快照索引与使用示例 | Sol检查实际输出；不让Luna自行选会计口径或制定验收答案 |
| 独立测试与审查 | 独立Sol | 先按规范计算预期值，再审实现；提出可复现失败样例，核修复 | 不由被审模块作者自己签署通过 |
| 高风险最终审查 | 主任务/Astra | 股东现金、少数权益、债务、摊薄、终值、价格反推、重复计数、Skill行为验收 | 依据独立算例和来源判断，不只阅读作者总结 |

先冻结公共字段、函数输入输出和文件归属，再并行开发互不冲突的模块。公共接口与核心skill由主任务统一合并；一个文件同一时刻只分配一个写入者。评审尽可能只拿规范、必要原始数据与待审模块，不复制整段50家公司研究历史。

对于研究时的价格隔离，经营输入和行情/卖方输入采用分别提供的文件清单与冻结记录。共享工作区中，子Agent并不天然获得文件权限隔离；仅移动目录或写“不要读取”不称作硬隔离。若要保证盲态，应另行验证受限工具或运行环境能否禁止读取价格资料。[OpenAI关于子Agent共享文件系统的说明](https://developers.openai.com/api/docs/guides/agents-api/multi-agent)

## 实施与验收顺序

1. **冻结规则和独立样例。** 主任务与审查Agent先确定字段、财务定义、版本规则及预期结果。开发者可以有自己的测试，但不能只用同一套函数正算/反算证明正确。
2. **做最小可用版本。** 完成标准化、历史指标、质量检查和结果导出。优先用既有数据验证，避免重复消耗接口和研究额度。
3. **复用真实错误回归。** 用8—10家差异较大的公司和人工构造边界样例验证。可选茅台、比亚迪、小熊、重庆啤酒、海天、中建、招商、平安、中信；真实期望值必须从原报与口径表独立确认，不能把Luna旧稿当标准答案。
4. **完善估值计算。** 基础层通过后加入有依据的财务调整、股本/分红、日期DCF、反推与回报。银行等未支持模型应明确拒绝通用估值，而不是输出零或任意目标价。
5. **对50家数据离线回放。** 检查字段覆盖、单位、版本、计算失败原因、重复运行结果；不重新生成50份完整研究。分别统计可计算比例和资料不足，不能以“无异常退出”冒充研究成功。
6. **接入skill并验证实际使用。** 从新的独立Agent任务调用财报skill、个股skill完成有限样例，检查是否真实调用程序、是否复用结果、是否正确保留缺口。最后出验收报告和剩余限制。

必要验收包括：

- 固定快照和规则下重复计算一致；时间戳等运行元数据与财务结果分开比较。
- 单位等价输入得到等价结果；报告中的值、单位和期次与机器结果一致。
- 一个明确整年后支付110、折现率10%、无其它现金流时，现值为100；复杂DCF再与独立逐期展开计算比较。
- 在期间与合并口径一致时，上一全年100＋本年上半年60－上年上半年40，TTM应为120；期间不兼容时必须拒算。
- 缺失不变零、冲突不静默消失，亏损/零基数不输出误导增速；资产负债表不被当累计流量。
- 本次十倍单位错、少数股东重复扣减、税前收益直接归因税后归母、日期错位、待付股息当已付、A/H混算、跨行业模板等具有对应失败样例。
- 反推不仅检查往返，还验证搜索区间、单调性、无解/多解处理及独立答案；不强行求出一个数。
- 有效输入可正常产出；研究资料不全时仍能交付已有事实和精确缺口，只拦截依赖该缺口的结果。

逐模块记录实际耗时、代理token与返工问题，不预先承诺节省百分比或固定开发费用。纯脚本重复运行不需要每次重新调用模型推算公式，但资料研究、异常解释和报告写作仍有模型成本。记录数据、公式、代码、展示、研究缺口五类问题，避免混成一个错误率。

## 如何接入三个核心 Skill

按现有项目约定，只维护项目 `Skills/` 下的规范源文件，全局软链接继续引用，不新增同名全局副本。

- **财报skill：** 在其`scripts/`维护数据适配与通用财务计算模块，详细字段/公式放现有`references/data-and-calculation-contract.md`或明确链接的新计算说明。入口只增加何时运行、如何提供输入、如何处理失败及如何引用结果。
- **个股skill：** 在现有DCF程序基础上维护估值模块，复用财报结果；新增明确日期、现金调整、股本/分红与反推接口。证据及输入不满足时保留条件测试/不适用边界，不让程序替研究者定假设。
- **行业skill：** 仅在有必要的同口径行业数字时引用确定性算术工具；行业定义、因果关系和未来状态仍由研究完成，不要求每篇行业报告运行估值。

共用部分单一实现，依赖通过实际路径解析或明确配置定位；跨项目调用验证软链接和路径，不硬编码本机用户目录。程序只读调用方指定输入、写调用方指定研究目录，运行时不把当期结果写回skill源文件。

接入前运行脚本的真实算例、独立复核和skill结构检查；结构检查通过只证明入口和文件格式有效。最终行为验收要证明Agent按要求调用程序并正确解释结果。保留既有脚本和skill的修改差异以便回退，不修改无关市场复盘工程。
