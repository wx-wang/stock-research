# 叙事估值数据源路由

这份契约把“事实”、“推断”、“市场叙事”和“估值观点”分开。不得因为某个数据源方便就让它越界证明其他类型的结论，也不得给整份来源贴一个统一证据标签。

## 1. 主张级证据处理

每份来源先拆成可单独验证的原子主张，再决定它能承担什么证据角色：

```text
Source
→ Extract Atomic Claim
→ Classify Claim
→ Assign Evidence Role
→ Trace Original Source / Lineage
→ Judge Evidence Confidence
→ Record Next Verification and Falsifier
```

### 1.1 主张分类

| 主张类别 | 回答的问题 | 可以做什么 | 不能做什么 |
|---|---|---|---|
| `Fact` | 截至某日已经发生了什么 | 建立产业、公司、财务和价格事实 | 自动证明未来持续性 |
| `Inference / Hypothesis` | 根据事实推断未来可能怎样 | 进入因果链和情景假设，前提是可验证、可证伪 | 冒充已发生事实 |
| `Market Narrative / Expectation` | 市场正在传播、预测或定价什么 | 生成问题、建立预期基线和分歧 | 覆盖经营事实或直接进入独立 Pass A |
| `Valuation View / Model Output` | 某组假设下价值或价格要求是什么 | 比较模型、反推价格隐含状态 | 证明订单、份额、盈利或真实共识 |

`变化`必须由两个同口径 Fact 比较得到。公司指引是前瞻性主张，不因写在公告中就成为未来事实。分析师引用的官方历史数字可作为 Fact 的二手载体，但其盈利预测和目标价分别属于 Expectation 与 Valuation View。

### 1.2 证据角色

每条证据只承担它实际能够完成的角色：`直接证明 / 交叉佐证 / 反证 / 口径校准 / 背景解释 / 生成问题 / 建立预期基线 / 估值输入`。同一证据可以承担多个角色，但必须逐项写清；“来源可靠”不能代替“能直接证明当前主张”。

### 1.3 Evidence Confidence

核心主张使用 `高 / 中 / 低`，不计算分数、不平均来源等级：

- **高：** 证据直接、接近原始事件，时间/范围/单位/定义完整且可复核，没有重大未解决冲突；或有真正独立的证据链一致支持。正式法律文本、审计财报中的确定科目等可由单一权威原始文件最终证明，不机械要求第二来源。
- **中：** 有明确证据但包含推导、样本或口径限制、仅有单一证据链、可靠二手整理或管理层自述。可形成暂时判断，但要写限制和下一验证。
- **低：** 原始来源或方法不清、只有摘要/转述、匿名传闻、样本很弱或只能间接支持。只能作为线索、叙事或待验证假设，不能单独验证关键事实，也不能独立决定 Pass A 参数。

判断维度是：对主张的直接性、距原始事件的距离、口径完整性、时效性、独立交叉验证和未解决冲突。置信度属于当前主张，不是来源永久属性。

### 1.4 来源血缘与独立性

记录：`Original Source → Secondary Source → Repost / Commentary`，并为同一根来源赋相同 `Lineage ID`。

- 公司财报、Tushare 对该财报的结构化字段、媒体转述和研报引用若都来自同一财报，只算一条原始证据链；
- 十篇研报引用同一协会统计，只提高该统计的传播度，不增加独立事实证据数量；
- 同一专家被多篇文章转述、同一渠道调查被多家机构引用，也只算一条证据链；
- 真正独立通常意味着不同原始生成过程，例如监管记录、客户采购数据、供应商出货和多家公司的可比披露；它们仍需检查是否在测量同一口径。

核心证据账本使用：

```text
Claim ID / 原子主张 / 主张类别 / 时间-范围-单位
证据角色 / Evidence Confidence
Original Source / Immediate Source / Lineage ID
独立原始证据数 / 同源转载数
支持证据 / 反证或冲突
关键假设 / 下一验证 / 证伪条件
```

报告正文只展示决定结论的主张。完整账本默认放入 `research_data/` 或独立的 `Research Notes / Evidence Appendix / Audit Log`，不进入主报告；只有用户明确要求审计时才随报告提供。证据质量若会改变结论，用普通语言说明限制，不输出内部字段。

## 2. 按研究问题选择数据来源

已验证的接口与权限限制见项目[数据渠道实测记录](../../../研究规则/数据渠道实测记录.md)。Tushare 资讯接口不能假设共享权限；IBKR 仅按已测范围作为证券检索、行情和公司关系的补充。

1. 股票基本信息、历史财务、行情、股数、业绩预告和卖方预测集，优先通过已安装的 Tushare MCP 获取，按接口分别确认权限。
2. 公司公告、财报附注、监管文件、政府和行业原始统计是核验关键事实的直接来源，按研究问题主动获取，不必等其他渠道失败。Web 搜索用于定位原文、寻找独立证据和补充消息。
3. 用已测可用的 Tushare `major_news`、Web 和知识星球「观察者03」搜集消息与市场观点；用户指定 IMA 知识库时一并检索。没有指定知识库不阻塞其他研究，也不假称已检索。新闻、社群、研报之间追溯同源转载。
4. 海外公司可按需用 IBKR 已测接口查询证券身份、报价及竞争者/产品资料；核对报价时间，公司关系中的数字与 evidence 文字不代替原始披露。其他市场和未测接口不得默认可用。
5. 研报原文通过研报 skill、用户材料或可访问链接获取，阅读时执行项目[券商研报阅读规则](../../../研究规则/券商研报阅读与方法提炼.md)。`report_rc` 的预测表与 `research_report` 的研报资料分开；后者无权限不代表前者不可用，前者返回也不代表已读全文。

### 选核心变量前的变化扫描

完整个股研究先按主要产品、子公司和利润来源发现候选变化，再收敛为 1–3 个核心变量。检索不能只围绕公司公告或已知叙事：结合产品与所在行业，查看相关的需求、有效供给、价格/价差、库存、贸易流向和政策准入在研究期内是否出现足以影响利润的变化。某一维度与该业务无关时不必机械搜齐。

用公司及子公司名称、主要产品和关键产业变量分别检索 Web、可用资讯接口及观察者03；优先追溯公告、监管、行业统计等根来源。记录重要候选的事件日、披露日、搜索词、证据强弱，以及需要补查的公司销量、价格、成本或税费。对异常股价、分部利润、税负或现金变化，反向寻找可能遗漏的产品和政策因素；同行同向变化是发现行业线索，不是公司已经受益的证明。

收敛前逐项问：变化是否落到公司的产品和实际可销售市场，影响多少销量与单位利润，何时进入归母利润和股东现金。配额、许可、报价及行业总量须与公司实际量区分。若潜在影响重大而公司层面数量尚缺，保留为关键未知并限制估值结论的确定性，不因暂时无法计算就从候选中删除。

## 3. Tushare MCP：股票基本信息与结构化数据的优先入口

使用已安装的 `mcp__tushareMcp__*` 工具，先发现所需工具并阅读参数定义，再按任务调用。股票基本信息优先用 `stock_basic`，公司介绍等资料按需用 `stock_company`；不依赖旧本地取数脚本，不因为脚本不存在就认定数据不可用，也不要求用户重新提供已配置的凭据。

以下表格主要列 A 股接口。港股主体用 `hk_basic`，行情用 `hk_daily`，财务用 `hk_income`、`hk_balancesheet`、`hk_cashflow` 等已暴露的对应工具；其他市场同样先确认工具及覆盖，不能把 A 股接口直接用于所有市场。数据库行业分类只是研究起点，不替代对实际业务和行业边界的分析。

按研究问题限制代码、日期、字段和返回范围，先取必要数据，再补缺口；检查分页、返回上限和空值。能发现工具不代表所有接口均有权限，某个接口测试成功不代表全部数据已验证。权限不足、限流或无数据时如实记录，改用公告等可核验来源，不无限重试。

查询最新行情时核对实际交易日期；历史研究只使用当时已公布的财报和预测。核对金额、股数和市值单位、币种、累计/单季口径，不能直接拼接不同市场的字段。研究正式使用的数据保存到 `research_data/`，记录工具名、参数、检索时间及原始返回；工具不会自动替项目完成归档。

| 任务 | 优先接口 | 必须保留的口径 |
|---|---|---|
| 主体确认 | `stock_basic` | 全称、简称、代码、市场、上市状态 |
| 股价与复权 | `daily`, `adj_factor`, `trade_cal` | 交易日、原始/复权口径、复权方法 |
| 市值、股数与交易口径 | `daily_basic` | 总市值/流通市值、总股本、流通股本、单位与日期 |
| 利润表 | `income` | 报告期、公告日、报表类型、合并口径 |
| 资产负债表 | `balancesheet` | 时点口径、重述与并表变化 |
| 现金流量表 | `cashflow` | 累计/单季、资本开支定义 |
| 财务指标 | `fina_indicator` | 指标定义、分子分母、是否年化 |
| 分部/主营 | `fina_mainbz` | 产品/地区类型、口径变化、加总是否可比 |
| 业绩更新 | `forecast`, `express`, `disclosure_date` | 预告/快报/定期报告不得混同 |
| 分红、回购、解禁与持股 | `dividend`, `repurchase`, `share_float`, `top10_holders`, `top10_floatholders` | 方案状态、股数及实施日期 |
| 券商预期 | `report_rc` （必要时补充研报索引） | 券商、报告日、预测年份、指标、样本数、区间/中位数 |

`report_rc` 是“可识别的卖方预测集”，不自动等于完整市场一致预期。单一研报不得称为“市场预期”。公司指引、卖方预测集、历史趋势和价格隐含预期必须分列。

每次调用保留：接口名、字段、参数、返回日期、单位、空值、原始响应文件路径和失败状态。原始数据存入 `research_data/`；不得用行业均值或前期值静默补齐空值。

## 4. 观察者03：市场叙事与分歧

使用 `zsxq` Skill，不猜测星球 ID：

1. 用 `group +list` 定位「观察者03」。
2. 围绕公司全称、简称、代码、核心业务/产品、具名竞争者和重要事件，用 `topic +search --group-id <id> --query "<关键词>" --json` 多词检索。
3. 按 `topic_id` 去重，对决策相关命中用 `topic +detail` 读全文，不只根据标题下结论。
4. 抽取发布日期、旧叙事、新证据、共识、分歧、催化剂、反方证据和所影响的估值变量。

搜索是语义/模糊召回，可能漏召或误召。内部必须记录关键词覆盖、命中数、全文复核数、最新日期及检索失败，不得将“未命中”解释为“市场没有这个叙事”。只有检索覆盖不足会实质影响预期差判断时，才在主报告中用一句自然语言说明。

## 5. IMA 知识库：研报、资料与叙事证据

使用 `ima-skill` 的知识库搜索能力。若用户指定了知识库名称，先用 `search_knowledge_base` 按名称定位，不得猜测或对用户展示内部 ID；再用 `search_knowledge` 多关键词检索。需要引用原文时，通过 `get_media_info` 获取媒体内容；若原文无法取得，显式标记“仅检索摘要/需要在 IMA 客户端复核”。

IMA 命中可以证明“某份资料或观点存在”，不能单独证明订单、客户、技术、市占率、收入或利润事实。关键事实应回到公告、Tushare、监管/政府/协会或另一类独立来源验证。

## 6. 叙事证据账本

每条重要叙事至少记录：

```text
主张 / 发布日期 / 来源类型 / 原文或仅摘要
它是事实、预测、观点还是传闻
支持证据 / 反方证据 / 独立核验状态
影响变量：行业需求 / 份额 / 单位经济 / 利润率 / 现金转化 / n / r / 终局持续性
下一验证日期与证伪条件
```

叙事必须最终映射到可计算变量；无法映射的叙事只作背景，不进入估值。

叙事账本同样记录根来源和 `Lineage ID`。多条帖子复述同一研报时，是一条预测来源和多次传播，不是多条独立共识证据。只有来源主体、信息形成过程和样本确实独立时，才能增加独立证据数。

## 7. 预期基线与事件更新

在独立经营底稿冻结后建立预期基线，分开公司指引、`report_rc` 卖方预测集、其他研报区间、可观察市场叙事和价格隐含状态。每项记录来源、发布日期、适用报告期、单位、样本范围及原始路径。后续结果只与当时已经存在的基线比较，不用事后预测回写事件前预期。

订单、客户、技术、扩产、政策或财报消息使用 [公司生意、核心驱动与预期差](company-business-drivers-and-expectations.md) 的事件更新记录。先核验事实和数量级，再映射到冻结的 1–3 个核心变量。不能确定收入确认、利润率、回款、资本投入或对应期间占比时，只能标为待验证线索；新闻标题、传播热度和股价反应不能替代财务影响。
